# База данных проекта клиенса — описание таблиц

Проект: система онлайн-записи для салонов красоты и мастеров.
База данных: SQLite (SQL, совместима с PostgreSQL).
Всего 6 таблиц.

---

## 1. business — профиль бизнеса

Хранит информацию о самом салоне или мастере.
В таблице всегда одна запись (id = 1), так как бизнес один.

| Поле | Тип | За что отвечает |
|---|---|---|
| id | integer | Уникальный номер, всегда 1 |
| name | text | Название салона, например «Салон красоты Роза» |
| address | text | Адрес салона — город, улица, дом |
| cover | text | Картинка-обложка (баннер) в виде кода Base64 |

---

## 2. services — услуги

Каталог услуг, которые оказывает салон (стрижка, укладка, маникюр).

| Поле | Тип | За что отвечает |
|---|---|---|
| id | text | Уникальный идентификатор услуги |
| name | text (обязательно) | Название, например «Мужская стрижка» |
| description | text | Краткое описание услуги |
| duration | integer | Длительность в минутах (например 50) |
| price | integer | Цена в рублях (например 1300) |
| active | integer | Активна ли услуга: 1 — да, 0 — нет |

---

## 3. masters — мастера

Сотрудники салона, которые оказывают услуги.

| Поле | Тип | За что отвечает |
|---|---|---|
| id | text | Уникальный идентификатор мастера |
| name | text (обязательно) | Имя мастера, например «Алина» |
| role | text | Должность, например «Барбер» |
| color | text | Цвет мастера для отображения в расписании (HEX-код) |
| bio | text | Описание мастера, опыт работы |
| photo | text | Фотография мастера в виде кода Base64 |
| active | integer | Принимает ли онлайн-запись: 1 — да, 0 — нет |

---

## 4. products — товары

Каталог товаров для продажи в салоне (шампуни, косметика).

| Поле | Тип | За что отвечает |
|---|---|---|
| id | text | Уникальный идентификатор товара |
| name | text (обязательно) | Название, например «Шампунь для волос» |
| price | integer | Цена в рублях |
| stock | integer | Сколько штук осталось на складе |
| active | integer | В продаже ли товар: 1 — да, 0 — снят |

---

## 5. slots — слоты времени

Свободные окошки для записи. Администратор создаёт их заранее.

| Поле | Тип | За что отвечает |
|---|---|---|
| id | text | Уникальный идентификатор слота |
| master_id | text (обязательно) | К какому мастеру относится слот (связь с masters.id) |
| date | text (обязательно) | Дата в формате YYYY-MM-DD, например 2026-11-18 |
| time | text (обязательно) | Время в формате HH:MM, например 10:00 |
| booked | integer | Занят ли слот: 0 — свободен, 1 — занят клиентом |

---

## 6. appointments — записи клиентов

Главная таблица. Здесь хранятся все записи клиентов.

| Поле | Тип | За что отвечает |
|---|---|---|
| id | text | Уникальный идентификатор записи |
| slot_id | text | На какой слот записался (связь с slots.id) |
| service_id | text | Какая услуга выбрана (связь с services.id) |
| master_id | text | К какому мастеру (связь с masters.id) |
| date | text (обязательно) | Дата визита |
| time | text (обязательно) | Время визита |
| client_name | text (обязательно) | Имя клиента |
| client_phone | text (обязательно) | Телефон клиента |
| client_email | text | Email для напоминания за 3 дня до визита |
| status | text | Статус: new (новый), done (выполнен), canceled (отменён) |
| created_at | text | Когда создана запись (дата и время) |

---

## Связи между таблицами

| Откуда → Куда | Тип | Что значит |
|---|---|---|
| masters → slots | один ко многим | У одного мастера много слотов времени |
| masters → appointments | один ко многим | Один мастер ведёт много записей |
| services → appointments | один ко многим | Одна услуга встречается во многих записях |
| slots → appointments | один к одному | Один слот = одна запись клиента |

---

## Почему business и products ни с чем не связаны

**business** — в таблице всегда одна запись (один салон). Все данные и так принадлежат этому салону, поэтому связь с другими таблицами избыточна. Если бы салонов было много, в каждую таблицу добавили бы поле business_id.

**products** — товары продаются отдельно от услуг. Клиент может купить шампунь без записи на стрижку. В полной версии можно добавить промежуточную таблицу appointment_products для учёта товаров, проданных во время визита.

---

## Расшифровка сокращений

- **PK** (Primary Key) — первичный ключ, уникальный идентификатор записи
- **FK** (Foreign Key) — внешний ключ, ссылка на другую таблицу
- **NN** (NOT NULL) — поле обязательное, пустым быть не может
- **integer** — целое число
- **text** — текст
- **Base64** — способ хранения картинки в виде текста
